# Claude Code 開発ルール

最終更新：2026-07-27

`CLAUDE.md` から参照される詳細ルール。プロダクトとして変えてはいけないことは
`docs/product-charter.md` を参照。ここでは「どう作業するか」を定める。

---

## 標準ループ（不具合対応・機能追加どちらにも使う）

1. 症状を再現、またはコード上で確認する
2. 関連ファイルを調査する（`docs/system-design.md` のディレクトリ構成を起点にする）
3. 原因候補を整理する
4. 証拠から原因を絞る（推測で決めつけない）
5. 修正方針を決定する（最小限の修正を優先）
6. 必要最小限の修正を行う
7. 関連するテストを実行する（`npm run test`）
8. 全体テスト・lint・buildを実行する
9. 差分を確認する（`git diff`）
10. `docs/product-charter.md` の不変条件に抵触していないか確認する
11. 完了報告する（形式は `CLAUDE.md` 参照）

テストやlintが失敗しても、すぐにMasterへ判断を求めない。原因調査と再修正を続ける。
ただし、**同じ修正方法を根拠なく何度も繰り返さない**。2〜3回試して解決しない場合は、
試した方法・分かったこと・残っている仮説を整理してMasterに報告する。

---

## 事実と推測を分ける

報告・調査メモでは常に次を区別する。

- **確認した事実**：実際に読んだコード、実行結果、DBスキーマ、ドキュメントの記載
- **推測**：まだ確認していない仮説、行間から予想されること

「〜だと思われる」「未確認だが」のような言葉で推測であることを明示する。
事実か推測か曖昧な書き方をしない。

---

## Supabase・migrationの扱い

- `supabase/migrations/README.md` が適用状況の正本。矛盾があれば触らず報告する。
- 001〜003は書き換えない。変更は必ず004以降の新規ファイルで行う。
- 004以降のSQLファイルの作成・編集はできるが、**Supabase SQL Editorでの実行はMasterが行う**。
  Claude CodeからSupabase CLIやAPI経由でmigrationを本番/開発DBに適用しない。
- `supabase/dev-tools/reset_dev_database.sql` はMasterの明示的な承認なしに実行しない。

---

## 自動で進めてよいこと（確認不要）

- ファイル読み取り、コード検索、ログ確認、`git diff` 確認
- 原因調査
- 可逆的なコード修正（ファイル単位でいつでも元に戻せる変更）
- `npm run test` / `npm run build` / `npm run lint` の実行
- 既存ドキュメントの整理（誤字修正、リンク切れの修正等）
- 必要なルールファイルの追加
- 修正に失敗した場合の再調査・再修正

## 必ず止まって確認すること

- `git push`
- 本番環境へのデプロイ
- Supabase本番データの削除・大量更新、migrationの本番適用
- データベースの reset / drop / truncate（`reset_dev_database.sql` を含む）
- 未コミット変更の破棄、`git reset --hard`、`git clean`、大量のファイル削除
- 履歴を書き換えるGit操作（rebase -i、force-push 等）
- secretsやAPIキーの変更・表示（`.env.local` の値を出力しない）
- 課金が発生する操作
- プロダクトの思想・対象者・主要仕様の変更（`docs/product-charter.md` 参照）
- 外部サービスへの公開

---

## ドキュメントの矛盾を見つけたとき

複数のドキュメント・コード・DBスキーマの間に矛盾を見つけた場合、
どのファイルが正本か自分で判断して書き換えない。矛盾点を `docs/current-status.md` に
追記し、報告の中でMasterに判断を仰ぐ。

---

## 完了条件

次をすべて満たすまで「完了」と報告しない。

- 依頼内容がコードに反映されている
- 関連テストが成功している
- 全体テスト（`npm run test`）が成功している、または実行できない理由が明確
- ビルド（`npm run build`）が成功している
- 既存の主要機能を壊していない（関連画面のコードを目視確認）
- `docs/product-charter.md` に反していない
- `git diff` を確認している
- 実施内容を初心者にも伝わる日本語で説明できる
